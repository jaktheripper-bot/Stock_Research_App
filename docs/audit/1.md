## 1. Summary

The site is **up and mostly healthy**. All 49 public routes and APIs tested return results, every page except stock dossiers loads in under 1 second, admin pages are correctly behind login, and all 279 local tests pass.

However, the audit found **three problems that put user trust at risk**. All three are live right now:

1. **Every large company is shown with made-up "sector benchmark" numbers.** INFY, TCS and RELIANCE all show ROCE 15.0%, Debt-to-Equity 0.25 and 3-Year Revenue CAGR 12.0%. These are fallback values in the code, presented to users as the company's real figures.
2. **Every large company fails the "illiquid shell" forensic check.** INFY, TCS, RELIANCE and HDFCBANK are all flagged `SUB_SCALE_ILLIQUID_SHELL` (CRITICAL) because their market cap is read as ₹0.0 Cr. As a result, dossiers show "Watchlist (1 Flags)" and "9/10 Passed".
3. **The site-wide "autonomous feed" shows test data to the public**, including a fake alert: *"Material disclosure detected for TESTCORP: Resignation of Statutory Auditor"*.

The next most important issues are **slow first loads of dossiers (24–37 seconds)**, **4 broken BSE links in every dossier header**, and a **public debt API that never responds**.

### 🔴 P0 — Shown to users now

#### F1. Sector benchmark numbers are placeholders presented as real company data
- **Where users see it:** The "Sector Benchmark Metrics vs Indian Industry Peers" panel on every dossier ([dossier.html:230-245](file:///Users/lyndonpinto/Documents/Stock_Research_App/web/templates/dossier.html#L230-L245)).
- **Evidence (live):**

  | Ticker | ROCE | D/E | Rev. CAGR | FCF Conv. |
  | :--- | :--- | :--- | :--- | :--- |
  | INFY | 15.0% | 0.25 | 12.0% | 82% |
  | TCS | 15.0% | 0.25 | 12.0% | 82% |
  | RELIANCE | 15.0% | 0.25 | 12.0% | — |
  | WIPRO | 15.0% | 0.25 | 12.0% | 82% |

- **Root cause:** [sector_scoring.py:207-212](file:///Users/lyndonpinto/Documents/Stock_Research_App/core/analysis/sector_scoring.py#L207-L212) quietly fills in `15.0`, `0.25` and `12.0` when the input data is missing. [Line 252](file:///Users/lyndonpinto/Documents/Stock_Research_App/core/analysis/sector_scoring.py#L252) hard-codes `fcf_conversion = 82.0` for every IT company.
- **Also:** The narrative text on [lines 275-276](file:///Users/lyndonpinto/Documents/Stock_Research_App/core/analysis/sector_scoring.py#L275-L276) always says *"Negligible leverage … strong ROCE"*, even when the KPI badges next to it say **ELEVATED** and **WATCH**. Users see both on the same card, and they contradict each other.
- **Rule broken:** AGENTS.md §2 (Zero-Hallucination).

#### F2. Every large company is falsely flagged as an "illiquid shell"
- **Where users see it:** The "360° Forensic Audit" tile, which shows "9/10 Passed · Watchlist (1 Flags)". The composite score is also lowered.
- **Evidence (live):** INFY, TCS, RELIANCE, HDFCBANK and WIPRO all return `red_flags: ["SUB_SCALE_ILLIQUID_SHELL"]` with the message *"Market capitalization ₹0.0 Cr is below institutional threshold (₹25.0 Cr)"*.
- **Root cause:** [chanakya.py:395](file:///Users/lyndonpinto/Documents/Stock_Research_App/core/cortex/chanakya.py#L395) looks for `market_cap_cr`, `mcap_cr` or `base_mcap`. The fundamentals feed supplies `market_cap` ([fundamentals.py:71](file:///Users/lyndonpinto/Documents/Stock_Research_App/core/analysis/fundamentals.py#L71)), so none of the keys match. The fallback `0 / 1e7 = 0.0` is a valid number, so the intended default of `100.0` never applies.
- **Why tests missed it:** The tests pass the market cap directly using the key the code expects, rather than the shape the live data feed produces.

#### F3. The public "autonomous feed" shows test data and a fake company alert
- **Where users see it:** `loadSurveillanceEvents()` ([main.js:1092-1125](file:///Users/lyndonpinto/Documents/Stock_Research_App/web/static/js/main.js#L1092-L1125)) is used by `base.html`, so the feed can appear on any page.
- **Evidence (live `/api/autonomous/events?limit=8`):** 5 of the 8 events are test data:
  - `test_bse_filing | unit_test | "Test autonomous event recording"` (twice)
  - `bse_material_filing | "Material disclosure detected for TESTCORP: Resignation of Statutory Auditor"` (twice)
  - `DAILY_FUND_AUDIT | TEST_SUITE_ROTATION | "Test automated 7-pillar look-through audit completed."`
- **Also:** The newest real event is from 2026-10-09 17:45. Nothing has been recorded since, so the "real-time" feed is stale.
- **Root cause:** Not yet determined. The test-mode guard in [connection.py:22](file:///Users/lyndonpinto/Documents/Stock_Research_App/core/db/connection.py#L22) and the auditor's test runner ([tools.py](file:///Users/lyndonpinto/Documents/Stock_Research_App/core/audit/tools.py)) both look correct. Test events reached the production database on 2026-10-08 and 2026-10-09 by some other route, possibly a one-off sync. The [`scripts/sync_to_supabase.py`](file:///Users/lyndonpinto/Documents/Stock_Research_App/scripts/sync_to_supabase.py) path is the first suspect to check.

#### F5. `/api/debt/securities` never responds
- **Evidence:** It timed out on all 4 attempts (60s, 60s, 90s, 90s, with and without filters). Locally it returns 27 securities in 0.7s.
- **Root cause:** Each of the 27 securities triggers a market-data lookup and an Angel One login attempt through `evaluate_equity_cross_contagion` ([debt_engine.py:901-909](file:///Users/lyndonpinto/Documents/Stock_Research_App/core/analysis/debt_engine.py#L901-L909)). That includes issuers that are not listed on the stock market, such as NABARD, NHAI and IRFC. Combined with the login retry problem in F4, this adds up to minutes.
- **Impact:** The site's own pages don't use this API, so `/debt` itself still loads in 0.2s. It is a public API, though, and anyone using it gets nothing back.

#### F6. Every dossier header has 4 broken BSE links — ✅ FIXED in `63cc83b` (verified live, §7)
- **Evidence (live, INFY and RELIANCE):** 3× `bseindia.com/stock-share-price/-/-/BSE Listed/` and 1× `Comp_Resultsnew.aspx?scrip_cd=BSE Listed`. The KPI tile also displays the text "BSE Listed" instead of the scrip code. Links inside the pillar sections are correct (`500209`, `500325`).
- **Root cause:** [main.py:962](file:///Users/lyndonpinto/Documents/Stock_Research_App/web/main.py#L962) passes `rep.get("scrip_code", "BSE Listed")` to the template, ignoring the correctly resolved `scrip_code` from [line 836](file:///Users/lyndonpinto/Documents/Stock_Research_App/web/main.py#L836).
- **Latent risk:** [dossier.html:58-79](file:///Users/lyndonpinto/Documents/Stock_Research_App/web/templates/dossier.html#L58-L79) falls back to `500209` (Infosys's scrip code) if the code is ever empty. Fixing the "BSE Listed" bug alone would make that fallback fire, so any stock without a code would link to the Infosys page.

#### F7. Market cap shows a double rupee sign: "₹₹4,15,324.03 Cr" — ✅ FIXED on dossiers in `63cc83b`; same bug on `/compare` found in §7 (F16)
- **Root cause:** [main.py:845](file:///Users/lyndonpinto/Documents/Stock_Research_App/web/main.py#L845) adds `₹` in front of `format_inr()`, which already adds one ([formatters.py:29](file:///Users/lyndonpinto/Documents/Stock_Research_App/core/formatters.py#L29)).

## 7. Visual Audit (2026-10-10, 17:05–17:16 IST)

### 7.1 Why the browser tool was failing (RCA)
- **Symptom:** The browser tool could not open any page.
- **Root cause:** The tool uses playwright-go 1.57.0. On first use it downloads its driver from `playwright.azureedge.net` and two mirror CDNs, and all three now return **HTTP 404** because Microsoft retired those legacy Azure CDN hosts. The cache folder `~/Library/Caches/ms-playwright-go/1.57.0/` had been created on 27 Sep but was empty, so every launch retried the download and failed. Node.js was not installed, so there was no fallback.
- **Fix:** Installed the driver into that folder by hand: the official Node v22 darwin-arm64 binary (SHA-256 checked against nodejs.org) and `playwright-core@1.57.0` from npm (SHA-1 checked against the registry). `node package/cli.js --version` now reports `Version 1.57.0`, and the browser tool opened `/health` successfully.
- **Note:** For the audit itself, the browser *subagent* was unavailable twice because its model had no server capacity (HTTP 503, outside our control). The audit was therefore run with the repaired driver, scripted against the system Google Chrome. Screenshots were reviewed by eye.
